Everything here is tracked in public, including the complaints. There is no
inbox: every route below ends in an issue or a pull request on the repository,
so you can follow what happens to it rather than wondering.

| If | Do this | It becomes |
| --- | --- | --- |
| A sentence on this page is wrong | **Something wrong here?** at the end of the section | an issue, with the section named |
| You want to reword one | **Edit this section** — the markdown is the source | a pull request against `docs/about/` |
| A statement misreads its paper | Review it: add, adjust or remove | an issue, checked by a bot, then a pull request |
| A paper is missing | Add it | a candidate for the scope scan |
| A question is clustered wrongly | Open an issue naming the question id | an issue |
| Anything else | The feedback form | an issue you can follow and reply on |

**Reviewing is the most useful thing.** {{reviewed}} of {{statements}}
statements have been judged by a person. Every other number here is waiting on
that one, and a verdict is recorded against your name in a pull request anyone
can read.

**A wrong question is usually a wrong note.** Each clustered question carries
a note saying why its statements are one question. If a cluster looks wrong,
read that note first: either it describes a question the statements are not
asking, or it is vague enough to cover anything. Both are worth an issue, and
the note is the thing to quote.

**Nothing is uploaded as you work.** A review lives in your browser until you
send it.
