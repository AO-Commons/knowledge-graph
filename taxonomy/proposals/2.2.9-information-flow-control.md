# Proposal: 2.2.9 Information-flow control for agent data access

**Status:** proposed, 2026-08-11
**Parent:** 2.2 Permissioning and capability control
**Proposed code:** 2.2.9

## Rationale

Section 2.2 covers permissioning thoroughly, but every existing child governs
*what an agent may reach*: credentials (2.2.2), grant duration (2.2.3), tool
access (2.2.5), network egress (2.2.6). None governs *what happens to data
once the agent has it*.

Information-flow control is a distinct mechanism with its own literature.
Data carries labels, the labels propagate through computation, and a policy
constrains where labelled data may end up. An agent can hold a credential
legitimately and still exfiltrate through a channel no egress rule covers —
summarising a confidential document into a public ticket, for instance. Least
privilege does not catch that, because no privilege was exceeded.

The gap matters more for agents than for conventional software: an LLM agent
routinely moves content between contexts as its ordinary mode of operation,
so the boundary that needs enforcing is the data's, not the caller's.

## Why existing topics are insufficient

- **2.2.1 Least privilege** — about the size of a grant, not the movement of
  data under it.
- **2.2.5 Tool access as the real permission surface** — closest, and still
  about reachability rather than propagation.
- **2.2.6 Egress and network reachability** — governs destinations at the
  network layer. IFC operates on values regardless of destination.
- **10.6 Defensive capability** — about defensive models, red teaming, and
  vendor filters, not access-control mechanism design.

Multi-tagging 2.2.5 + 2.2.6 would put the paper somewhere findable while
describing it as something it is not.

## Example resources

- Securing AI Agents with Information-Flow Control (arXiv:2505.23643) —
  currently tagged 2.2 + 10.1 + 10.6, none of which is what it is about.

One resource is thin evidence for a new topic. The argument for adding it
anyway is that IFC is an established technique arriving in this field rather
than a speculative one, so the node is likely to fill. **If leadership would
rather wait for a second and third resource, the honest interim move is an
alias on 2.2.5** and a note here.
