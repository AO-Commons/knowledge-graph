# Taxonomy proposals

One file per proposal, named `<proposed-code>-<slug>.md`.

Before writing one, work through the cheaper options in order: an **alias**, then **multi-tagging** across existing topics, then a **cross-link**. Most gaps are findability problems, not structural ones.

A proposal states:

- the proposed code and its parent
- the title
- the rationale
- example resources that need it
- why the existing topics are insufficient

Two rules that don't bend: codes are never renumbered or reused, and V1 adds no new top-level sections unless the corpus shows a persistent gap none of the 16 can hold.

A proposal is not accepted because a model suggested the concept. It is accepted because real resources have nowhere to go.
